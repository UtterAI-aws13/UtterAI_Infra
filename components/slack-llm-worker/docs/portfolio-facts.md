# README·포트폴리오에 사용할 수 있는 사실

이 문서는 다른 포트폴리오 섹션을 수정하지 않는, 이 워커에 한정한 문구와 근거입니다. 최종 수치는 [검증 기록](verification.md)과 함께 제시하세요.

## 사용 가능한 문구

> Slack 요청 수신과 LLM 실행을 큐로 분리한 비동기 워커를 구현했다. 재전달 시 모델 결과를 재사용하고, Slack이 답글을 수신했는지 불명확한 장애에서는 자동 재전송을 중단하도록 상태 전이를 설계했다. 로컬 HTTP·모의 SQS/모델/Slack 실험에서 100개 고유 이벤트를 200회 전달해 모델 호출 100회·답글 100개를 확인했고, timeout·저장 실패·lease 만료 등 58개 테스트를 통과했다. AWS·Slack 실서비스 검증은 진행 전이다.

문제 → 해결 → 결과의 연결:

| 문제 | 구현한 판단/해결 | 검증된 범위 |
|---|---|---|
| Slack 재시도와 SQS 재전달로 동일 요청 반복 | durable CAS claim·owner lease·완료 상태 | 동시 100회 동일 키 handle 호출에서 1회 실행 |
| 답변 생성 후 Slack 429가 오면 불필요한 모델 비용 재발생 | 결과 checkpoint 후 전송만 재시도 | 모의 429 후 모델 호출 1회 유지 |
| Slack 수신 직후 응답 유실로 자동 재전송하면 중복 답글 가능 | POSTING·AMBIGUOUS 상태, 자동 재전송 중단 | 모의 원격 수신+timeout/상태 저장 실패 주입 |
| 채널 제한 때문에 큐 반환을 반복하면 정상 작업이 DLQ로 이동 | 소비 중 슬롯 내 짧은 대기·heartbeat | 같은 100개 요청 실험에서 수정 후 DLQ 0 |
| 단일 입력에 API 서버를 별도 운영할 부담 | Lambda → SQS 최소 구성 선택 | 구조·배포 단위 비교. 실제 비용 절감액 미측정 |

## 주장하면 안 되는 것

- 'AWS에서 100개 동시 요청 처리', '운영 ACK p95 0.403ms', 'cold start 포함 3초 보장'.
- 'exactly-once Slack 답글', '중복/유실 완전 제거', '무중단·완전 자동 복구'.
- 'AWS 비용 X% 절감', '모델 비용이 절반', '운영 트래픽으로 입증'.
- '벡터 RAG·자율 tool agent·UtterAI 연계 완료', '실제 Bedrock 품질 검증'.
- '서명 검증·SQS 사용 자체가 독창적 혁신'. 해당 기능은 기본 구성 요소다.

강조할 수 있는 차이는 기본 기능의 나열보다 **외부 전송의 불확실성을 숨기지 않은 상태 설계와, 재시도 정책이 정상 트래픽을 DLQ로 보내는 문제를 재현해 수정한 과정**입니다. 가용성을 일부 양보하는 대가와 실서비스 미검증 범위를 함께 설명해야 합니다.
