# PodCrashLooping 대응 런북

대상 알림: PodCrashLooping, KubePodNotReady (api)

1. `/ops status api`로 Ready 수와 재시작 횟수를 확인한다.
2. 최근 배포가 없고 재시작 횟수만 늘고 있다면, 일시적인 연결 고갈이나 메모리 누수일 가능성이 높다. 이 경우 api 재시작(rollout restart)을 요청한다. 재시작은 다른 운영자의 승인을 받는다.
3. 최근 배포 직후라면 재시작하지 말고 이전 버전으로 롤백을 검토한다(이 봇은 롤백을 지원하지 않는다).
4. 재시작 후 10분 안에 같은 알림이 다시 오면 재시작을 반복하지 말고 담당자를 호출한다.
